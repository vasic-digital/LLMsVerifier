LLM Verifier Tutorials

Learn how to use LLM Verifier with these step-by-step tutorials.

Tutorial 1: Basic Model Verification

Learn how to verify a single AI model in under 5 minutes.

Step 1: Set Up API Key

export OPENAI_API_KEY="sk-your-api-key"

Step 2: Run Verification

llm-verifier verify --provider openai --model gpt-4o

Step 3: Review Results

Verification Results:
--------------------------------------------------
Model:    gpt-4o
Provider: openai
Status:   VERIFIED
Score:    0.95/1.0
--------------------------------------------------

Capabilities Tested:
  [PASS] Code generation
  [PASS] Reasoning
  [PASS] Context handling
  [PASS] Response quality
  [PASS] Error handling

Model is ready for production use!

Success!

You've verified your first model. The score of 0.95 indicates excellent performance.

Tutorial 2: Batch Testing Multiple Models

Test multiple models across providers in a single command.

Step 1: Create Models File

cat > models.txt << EOF
openai:gpt-4o
openai:gpt-4-turbo
anthropic:claude-3-5-sonnet-latest
anthropic:claude-3-opus-latest
google:gemini-2.0-flash
EOF

Step 2: Run Batch Verification

llm-verifier batch \
  --models-file models.txt \
  --parallel 3 \
  --output results.json

Step 3: Generate Report

llm-verifier report --input results.json --format html

Tutorial 3: Export Configuration for OpenCode

Generate OpenCode-compatible configuration to resolve ProviderInitError.

Step 1: Verify Models

llm-verifier verify --all-providers

Step 2: Export Configuration

llm-verifier export-config opencode \
  --output opencode-config.json \
  --verified-only \
  --include-api-keys

Step 3: Use in OpenCode

# Copy to OpenCode config directory
cp opencode-config.json ~/.opencode/providers.json

# Restart OpenCode
opencode restart

Security Note

The --include-api-keys flag embeds API keys in the config. Keep this file secure and don't commit to version control.

Tutorial 4: CI/CD Integration

Add model verification to your CI/CD pipeline.

GitHub Actions Example

name: Model Verification

on:
  schedule:
    - cron: '0 6 * * *'  # Daily at 6 AM
  workflow_dispatch:

jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Install LLM Verifier
        run: |
          go install github.com/llm-verifier/llm-verifier@latest

      - name: Verify Critical Models
        env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          llm-verifier batch \
            --models gpt-4o,claude-3-5-sonnet-latest \
            --output results.json

      - name: Check Results
        run: |
          failed=$(jq '[.[] | select(.score < 0.7)] | length' results.json)
          if [ "$failed" -gt 0 ]; then
            echo "Some models failed verification"
            exit 1
          fi

Tutorial 5: Continuous Monitoring

Set up continuous monitoring for model health.

Start Monitoring

llm-verifier monitor \
  --models gpt-4o,claude-3-5-sonnet-latest \
  --interval 300 \
  --duration 86400 \
  --alert-threshold 0.7 \
  --webhook https://hooks.slack.com/your-webhook

Prometheus Metrics

# prometheus.yml
scrape_configs:
  - job_name: 'llm-verifier'
    static_configs:
      - targets: ['localhost:8080']
    metrics_path: /metrics
