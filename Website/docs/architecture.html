Core Components

1. API Server

The API server provides REST and gRPC interfaces for all operations:

  • REST API - HTTP endpoints for web clients
  • gRPC API - High-performance binary protocol
  • WebSocket - Real-time updates and streaming

2. Verification Engine

The core verification system that tests AI models:

  • Model Verifier - Runs verification tests
  • Scoring System - Calculates verification scores
  • Challenge Runner - Executes test challenges

3. Provider Adapters

Unified interface for 20+ AI providers:

  • Base Adapter - Common interface for all providers
  • Model Discovery - Automatic model detection
  • Rate Limiting - Provider-specific rate limits
  • Failover - Automatic retry and fallback

4. Configuration System

Export verified configurations to multiple formats:

  • OpenCode - OpenCode JSON format
  • Crush - Crush configuration format
  • Claude Code - Claude Code settings

Provider System

The provider adapter pattern enables unified access to diverse AI providers:

type Provider interface {
    // Core operations
    Verify(model string) (*VerificationResult, error)
    Chat(request *ChatRequest) (*ChatResponse, error)

    // Model management
    ListModels() ([]Model, error)
    GetModel(id string) (*Model, error)

    // Health and status
    HealthCheck() (*HealthStatus, error)
    GetCapabilities() *Capabilities
}

Database Layer

LLM Verifier uses SQLite with SQLCipher for encrypted local storage:

Key Features

  • SQLCipher Encryption - AES-256 database encryption
  • Connection Pooling - Efficient connection management
  • Migrations - Automatic schema updates
  • Caching - Optional Redis caching layer

Schema Overview

-- Core tables
CREATE TABLE providers (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    api_key_hash TEXT,
    config JSON,
    created_at TIMESTAMP
);

CREATE TABLE verifications (
    id TEXT PRIMARY KEY,
    provider_id TEXT REFERENCES providers(id),
    model_id TEXT NOT NULL,
    score REAL,
    results JSON,
    verified_at TIMESTAMP
);

CREATE TABLE models (
    id TEXT PRIMARY KEY,
    provider_id TEXT REFERENCES providers(id),
    name TEXT NOT NULL,
    capabilities JSON,
    pricing JSON,
    verified BOOLEAN DEFAULT FALSE
);

Security Architecture

Security Layers

  • API Authentication - JWT token-based auth
  • Database Encryption - SQLCipher AES-256
  • API Key Protection - Encrypted storage, never logged
  • Rate Limiting - Per-user and per-IP limits
  • Input Validation - Strict input sanitization
  • Audit Logging - Comprehensive audit trail

Enterprise Security

LLM Verifier follows SOC 2 compliant security practices. See our Security Documentation for details.
