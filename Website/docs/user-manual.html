User Manual

Complete documentation for all LLM Verifier features, commands, and configuration options.

Overview

LLM Verifier is an enterprise-grade platform for verifying, monitoring, and optimizing Large Language Model (LLM) performance across multiple providers. It helps you:

  • Verify model availability and capabilities
  • Generate configuration files for AI coding tools
  • Calculate comprehensive model scores
  • Monitor provider health and performance
  • Export verified configurations to multiple formats
Note: All verified models include the (llmsvd) suffix to indicate successful verification.

CLI Commands

Global Flags

llm-verifier [command] [flags]

Global Flags:
  --config string    Config file path (default "config.yaml")
  --verbose          Enable verbose output
  --json             Output in JSON format
  --quiet            Suppress non-essential output
  --help             Show help for any command

Core Commands

verify

Verify one or more models from a provider:

# Verify a single model
llm-verifier verify --provider openai --model gpt-4o

# Verify multiple models
llm-verifier verify --provider openai --model gpt-4o,gpt-4,gpt-3.5-turbo

# Verify all models from a provider
llm-verifier verify --provider openai --all

# Parallel verification
llm-verifier verify --provider openai --model gpt-4o,gpt-4 --parallel 2

# With timeout
llm-verifier verify --provider anthropic --model claude-3-opus --timeout 60s

discover

Discover available models from a provider:

# List all available models
llm-verifier discover --provider openai

# Discover and verify
llm-verifier discover --provider anthropic --verify

# Filter by capability
llm-verifier discover --provider openai --capability code-generation

export-config

Export verified configurations:

# Export to OpenCode format
llm-verifier export-config opencode --output config.json

# Export specific providers
llm-verifier export-config opencode --providers openai,anthropic

# Include API keys (secure environments only)
llm-verifier export-config opencode --include-api-keys

# Export to other formats
llm-verifier export-config crush --output crush.json
llm-verifier export-config claude-code --output claude.json

config

Manage configuration:

# Validate configuration
llm-verifier config validate

# Show current configuration
llm-verifier config show

# Initialize new configuration
llm-verifier config init

# Merge configurations
llm-verifier config merge source.json target.json

providers

Manage providers:

# List all providers
llm-verifier providers list

# Add custom provider
llm-verifier providers add \
  --name my-provider \
  --endpoint https://api.example.com/v1 \
  --api-key $MY_API_KEY

# Remove provider
llm-verifier providers remove my-provider

# Test provider connection
llm-verifier providers test openai

server

Run the API server:

# Start server with default settings
llm-verifier server

# Custom port
llm-verifier server --port 9090

# With authentication enabled
llm-verifier server --auth-enabled

# Development mode
llm-verifier server --dev

Verification Process

What Gets Verified

LLM Verifier performs comprehensive checks on each model:

Check Description
Availability Model responds to API requests
Authentication API key is valid and has proper permissions
Response Quality Model produces coherent, valid responses
Capabilities Code generation, streaming, multimodal support
Latency Response time within acceptable thresholds
Token Limits Context window and output limits

"Do You See My Code?" Test

A key verification test where the model is presented with code snippets and asked to identify or analyze them. This verifies:

  • Code understanding capability
  • Context retention
  • Accurate response generation

Scoring System

Each model receives a composite score (0-10) based on five weighted components:

Score Components

Component Weight Factors
Speed 20% First token latency, tokens per second, total response time
Efficiency 20% Context utilization, token economy, output quality per token
Cost 15% Price per 1K tokens (input/output), value for performance
Capability 30% Code generation, reasoning, multimodal, streaming, function calling
Recency 15% Knowledge cutoff date, model release date, update frequency

Score Interpretation

  • 9.0 - 10.0: Exceptional - Top-tier model for all use cases
  • 8.0 - 8.9: Excellent - Highly capable, recommended for production
  • 7.0 - 7.9: Good - Solid performer with some limitations
  • 6.0 - 6.9: Adequate - Suitable for specific use cases
  • Below 6.0: Limited - Consider alternatives

The (SC:X.X) Suffix

Verified models display their score in the format model-name (SC:X.X). For example:

gpt-4o (SC:8.5)
claude-3-opus (SC:9.0)
gemini-pro (SC:7.8)

Configuration

Configuration File

Create a config.yaml file:

global:
  base_url: "https://api.openai.com/v1"
  timeout: 30s
  max_retries: 3
  retry_delay: 1s

llms:
  - name: openai
    endpoint: "https://api.openai.com/v1"
    api_key: "${OPENAI_API_KEY}"
    models:
      - gpt-4o
      - gpt-4
      - gpt-3.5-turbo

  - name: anthropic
    endpoint: "https://api.anthropic.com"
    api_key: "${ANTHROPIC_API_KEY}"
    models:
      - claude-3-opus
      - claude-3-sonnet

database:
  path: "./llm-verifier.db"
  encryption_key: "${DB_ENCRYPTION_KEY}"

api:
  port: "8080"
  jwt_secret: "${JWT_SECRET}"
  rate_limit: 100  # requests per minute

verification:
  parallel_workers: 4
  timeout: 60s
  retry_on_failure: true

scoring:
  weights:
    speed: 0.20
    efficiency: 0.20
    cost: 0.15
    capability: 0.30
    recency: 0.15

Environment Variables

All configuration values support environment variable substitution using ${VAR_NAME} syntax. Required variables:

# Provider API Keys
export OPENAI_API_KEY="sk-..."
export ANTHROPIC_API_KEY="sk-ant-..."
export GEMINI_API_KEY="..."
export GROQ_API_KEY="gsk_..."
export DEEPSEEK_API_KEY="..."

# Database
export DB_ENCRYPTION_KEY="your-32-byte-key"

# API Server
export JWT_SECRET="your-jwt-secret"

Export Formats

OpenCode Format

Configuration for OpenCode AI coding assistant:

{
  "llms": {
    "openai": {
      "endpoint": "https://api.openai.com/v1",
      "models": ["gpt-4o (SC:8.5)", "gpt-4 (SC:8.2)"]
    }
  }
}

Crush Format

Configuration for Crush code completion:

{
  "providers": [
    {
      "name": "openai",
      "url": "https://api.openai.com/v1",
      "verified_models": ["gpt-4o", "gpt-4"]
    }
  ]
}

Claude Code Format

Configuration for Claude Code CLI:

{
  "model_configs": {
    "claude-3-opus (SC:9.0)": {
      "provider": "anthropic",
      "verified": true
    }
  }
}

Generic JSON

Raw verification data in JSON format for custom integrations.

Database

LLM Verifier uses SQLite with SQL Cipher encryption for storing verification results, configuration, and metrics.

Database Commands

# Initialize database
llm-verifier db init

# Migrate to latest schema
llm-verifier db migrate

# Backup database
llm-verifier db backup --output backup.db

# Query verification history
llm-verifier db query "SELECT * FROM verifications LIMIT 10"

Data Retention

Configure retention policies in your configuration:

database:
  retention:
    verifications: 90d    # Keep verification records for 90 days
    metrics: 365d         # Keep metrics for 1 year
    logs: 30d             # Keep logs for 30 days

Monitoring

Prometheus Metrics

LLM Verifier exposes metrics at /metrics:

  • llm_verifier_verifications_total - Total verification count
  • llm_verifier_verification_duration_seconds - Verification duration histogram
  • llm_verifier_provider_health - Provider health status (0/1)
  • llm_verifier_api_requests_total - API request count
  • llm_verifier_score_distribution - Score distribution by provider

Health Endpoints

# Health check
curl http://localhost:8080/health

# Ready check
curl http://localhost:8080/ready

# Detailed status
curl http://localhost:8080/status

Automation

CI/CD Integration

# GitHub Actions example
- name: Verify AI Models
  run: |
    llm-verifier verify --provider openai --all --json > results.json
    llm-verifier export-config opencode --output config.json
  env:
    OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}

- name: Upload Configuration
  uses: actions/upload-artifact@v3
  with:
    name: llm-config
    path: config.json

Scheduled Verification

# Cron job for daily verification
0 6 * * * /usr/local/bin/llm-verifier verify --all --json >> /var/log/llm-verifier.log

Integrations

Webhooks

Configure webhooks for verification events:

webhooks:
  - url: "https://your-server.com/webhook"
    events:
      - verification.completed
      - verification.failed
      - provider.down
    secret: "${WEBHOOK_SECRET}"

Slack Notifications

notifications:
  slack:
    webhook_url: "${SLACK_WEBHOOK_URL}"
    channel: "#ai-ops"
    events:
      - verification.failed
      - provider.down

Security

API Key Management

  • API keys are never logged or stored in plain text
  • Use environment variables for all sensitive values
  • Rotate keys regularly through your provider's dashboard

Database Encryption

LLM Verifier uses SQL Cipher for at-rest encryption. Generate a strong encryption key:

openssl rand -hex 32

JWT Authentication

API endpoints require JWT authentication when --auth-enabled:

# Generate token
curl -X POST http://localhost:8080/auth/login \
  -d '{"username":"admin","password":"password"}' \
  -H "Content-Type: application/json"

# Use token
curl http://localhost:8080/api/v1/models \
  -H "Authorization: Bearer <token>"
