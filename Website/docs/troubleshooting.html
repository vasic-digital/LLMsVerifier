Troubleshooting Guide

Solutions for common issues when using LLM Verifier.

ProviderInitError

The most common error when using OpenCode with LLM Verifier configurations.

Error

ProviderInitError: Failed to initialize provider 'openai': invalid configuration

Causes

  • Invalid JSON format in configuration file
  • Missing required fields (api_key, base_url)
  • Incorrect model names
  • API key format issues

Solution

Use LLM Verifier to generate a valid configuration:

# Generate verified configuration
llm-verifier export-config opencode \
  --output opencode-config.json \
  --verified-only

# Validate the configuration
llm-verifier validate-config opencode-config.json

# Copy to OpenCode directory
cp opencode-config.json ~/.opencode/providers.json

Configuration Checklist

  • API key is valid and not expired
  • Base URL is correct for the provider
  • Model names match provider's API
  • JSON syntax is valid (no trailing commas)
  • Required fields are present

API Errors

401 Unauthorized

Error: API request failed: 401 Unauthorized

Solution: Check your API key:

# Verify API key is set
echo $OPENAI_API_KEY

# Test API key directly
curl -H "Authorization: Bearer $OPENAI_API_KEY" \
  https://api.openai.com/v1/models

429 Rate Limited

Error: Rate limit exceeded. Please retry after 60 seconds.

Solution: Reduce request rate or upgrade API plan:

# Use rate limiting options
llm-verifier verify --provider openai \
  --rate-limit 10 \
  --retry-delay 5

500 Server Error

Error: Provider returned 500 Internal Server Error

Solution: Provider issue - retry later or check provider status:

# Check provider health
llm-verifier health --provider openai

# Use retry logic
llm-verifier verify --provider openai \
  --retry 3 \
  --retry-delay 10

Authentication Issues

API Key Not Found

Error: API key not found for provider 'anthropic'

Solution: Set the environment variable:

# Set API key
export ANTHROPIC_API_KEY="sk-ant-your-key"

# Or use config file
llm-verifier config set anthropic.api_key "sk-ant-your-key"

Invalid API Key Format

Error: Invalid API key format for provider 'openai'

Solution: Verify key format matches provider requirements:

  • OpenAI: Starts with sk-
  • Anthropic: Starts with sk-ant-
  • Google: Alphanumeric string

Verification Failures

Low Verification Score

Warning: Model gpt-3.5-turbo scored 0.65 (below threshold 0.7)

Causes:

  • Model limitations for code tasks
  • API quota restrictions affecting response quality
  • Temporary provider issues

Solution:

# Get detailed score breakdown
llm-verifier verify --provider openai \
  --model gpt-3.5-turbo \
  --verbose

# Try with different model
llm-verifier verify --provider openai \
  --model gpt-4o

Timeout Errors

Error: Verification timed out after 30 seconds

Solution: Increase timeout:

llm-verifier verify --provider openai \
  --model gpt-4o \
  --timeout 60

Configuration Errors

Invalid JSON

Error: Failed to parse config: unexpected end of JSON input

Solution: Validate JSON syntax:

# Validate config file
llm-verifier validate-config config.json

# Use jq to check JSON
cat config.json | jq .

Missing Required Fields

Error: Configuration missing required field 'api_key'

Solution: Ensure all required fields are present:

{
  "providers": {
    "openai": {
      "api_key": "${OPENAI_API_KEY}",
      "base_url": "https://api.openai.com/v1",
      "models": ["gpt-4o", "gpt-4-turbo"]
    }
  }
}

Performance Issues

Slow Verification

Verification taking too long:

# Use parallel processing
llm-verifier batch \
  --models gpt-4o,claude-3-opus \
  --parallel 5

# Skip slow tests
llm-verifier verify --provider openai \
  --skip-slow-tests

High Memory Usage

Reduce memory consumption:

# Limit batch size
llm-verifier batch \
  --models-file models.txt \
  --batch-size 10

# Disable caching
llm-verifier verify --no-cache

Debug Mode

Enable verbose logging for troubleshooting:

# Enable debug output
llm-verifier verify --provider openai \
  --model gpt-4o \
  --debug \
  --verbose

# Save debug log to file
llm-verifier verify --provider openai \
  --model gpt-4o \
  --debug 2>&1 | tee debug.log

Log Analysis

Check logs for detailed error information:

# View application logs
tail -f ~/.llm-verifier/logs/app.log

# Search for errors
grep -i error ~/.llm-verifier/logs/app.log

# View last 100 lines
tail -100 ~/.llm-verifier/logs/app.log
