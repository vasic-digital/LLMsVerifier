Getting Started with LLM Verifier

This guide will help you install LLM Verifier, configure your API keys, and run your first model verification in under 5 minutes.

Installation

Using Go Install

The easiest way to install LLM Verifier is using Go:

go install github.com/llm-verifier/llm-verifier@latest

Download Binary

Pre-built binaries are available for all major platforms:

Linux (x64) macOS (Intel) macOS (Apple Silicon) Windows (x64)

Docker

docker pull llmverifier/llm-verifier:latest
docker run -it llmverifier/llm-verifier verify --help

Build from Source

git clone https://github.com/llm-verifier/llm-verifier.git
cd llm-verifier
make build
./bin/llm-verifier --version

Configuration

API Keys Setup

LLM Verifier requires API keys for the providers you want to test. Set them as environment variables:

# OpenAI
export OPENAI_API_KEY="sk-your-openai-key"

# Anthropic
export ANTHROPIC_API_KEY="sk-ant-your-anthropic-key"

# Google Gemini
export GEMINI_API_KEY="your-gemini-key"

# Groq
export GROQ_API_KEY="gsk_your-groq-key"

# Additional providers...
export DEEPSEEK_API_KEY="your-deepseek-key"
export MISTRAL_API_KEY="your-mistral-key"

Configuration File

Alternatively, create a config.yaml file:

global:
  base_url: "https://api.openai.com/v1"
  timeout: 30s
  max_retries: 3

llms:
  - name: openai
    endpoint: "https://api.openai.com/v1"
    api_key: "${OPENAI_API_KEY}"

  - name: anthropic
    endpoint: "https://api.anthropic.com"
    api_key: "${ANTHROPIC_API_KEY}"

database:
  path: "./llm-verifier.db"
  encryption_key: "${DB_ENCRYPTION_KEY}"

api:
  port: "8080"
  jwt_secret: "${JWT_SECRET}"

Verify Configuration

llm-verifier config validate
llm-verifier config show

Run Your First Verification

Single Model Verification

# Verify a specific model
llm-verifier verify --provider openai --model gpt-4o

# Verify with detailed output
llm-verifier verify --provider openai --model gpt-4o --verbose

# Verify multiple models in parallel
llm-verifier verify --provider openai --model gpt-4o,gpt-4,gpt-3.5-turbo --parallel 3

Provider Discovery

# Discover all available models from a provider
llm-verifier discover --provider openai

# Discover and verify all models
llm-verifier discover --provider anthropic --verify

Understanding Verification Results

Each verification produces a score based on:

  • Response Speed - Latency and throughput metrics
  • Model Efficiency - Context handling and token efficiency
  • Cost Effectiveness - Price-to-performance ratio
  • Capability - Code generation, reasoning, and features
  • Recency - Model freshness and knowledge cutoff

Export Configuration

OpenCode Format

Generate OpenCode-compatible configuration to resolve ProviderInitError:

# Export verified models to OpenCode format
llm-verifier export-config opencode --output opencode-config.json

# Include API keys in export (secure environments only)
llm-verifier export-config opencode --output opencode-config.json --include-api-keys

# Export specific providers
llm-verifier export-config opencode --providers openai,anthropic --output config.json

Other Export Formats

# Crush format
llm-verifier export-config crush --output crush-config.json

# Claude Code format
llm-verifier export-config claude-code --output claude-config.json

# Generic JSON
llm-verifier export-config json --output models.json

Using Exported Configuration

Copy the generated configuration to your OpenCode installation:

# Copy to OpenCode config directory
cp opencode-config.json ~/.config/opencode/config.json

# Or merge with existing config
llm-verifier config merge opencode-config.json ~/.config/opencode/config.json

Troubleshooting

ProviderInitError

If you encounter ProviderInitError in OpenCode, follow these steps:

  1. Verify your API keys are valid: llm-verifier verify --provider openai
  2. Check the configuration format: llm-verifier config validate
  3. Export fresh configuration: llm-verifier export-config opencode
  4. Verify the exported file matches OpenCode schema

Common Issues

API Key Invalid
Ensure your API key is correctly set and has not expired. Test with: llm-verifier verify --provider <name>
Rate Limiting
Use --parallel 1 flag to avoid rate limits during verification.
Timeout Errors
Increase timeout with --timeout 60s for slower models or connections.
Database Lock
Ensure only one instance of LLM Verifier is running, or use --db-path to specify a different database file.
